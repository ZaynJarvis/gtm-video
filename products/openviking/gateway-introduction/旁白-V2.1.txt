主流 Agent 装上 OpenViking 插件，召回和沉淀全自动，换个 Agent，记忆还在。

可企业自己开发的 Agent，用几步模型调用串成的对话机器人，没有插件可装。新对话照样从零开始；想接上记忆，就得自己写检索、注入、保存，一个应用接一遍。

OpenViking 网关，换一种接法。把模型地址指向网关，密钥换成 OpenViking API Key。不装插件，不改业务代码。

同一个应用，同一个模型，同一个问题。这一次，它答得上来。

OpenViking 网关是一个模型代理，位于你的应用和模型之间。插件要装进每个 Agent；网关只守在通往模型的路上——每个应用经过这里，都自动带上记忆，也留下记忆。

每条新消息，网关先去 OpenViking 找相关记忆，附在消息后面，交给你原来的模型。要查得更细，模型会自己调用工具，网关代为执行。应用收到的，始终是一条完整回复；聊过的内容存回 OpenViking，变成下一次的记忆。

记忆跟着人走，不跟着应用。周一在研发助手里交代的习惯，周三换到运维机器人，它照样记得。

在火山引擎公有云上，网关开通即用，无需部署。全团队一个地址：服务商密钥留在网关，每人一把 API Key，随时吊销；记忆按人隔离，日志脱敏可查，安全和隐私都有保障。

OpenViking 网关，即将登陆火山引擎公有云。改两项设置，让你的应用接上记忆。
