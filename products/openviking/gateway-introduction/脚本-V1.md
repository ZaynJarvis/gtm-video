## 一句话

**不装插件，不改代码：客户端只改地址和密钥，模型就有了记忆。**

这句话直接取自官网，是整片的主张。全片只证明这一件事，再补两点：为什么可靠（工作原理），以及企业怎么管（团队）。

## 看完要记住的三件事

| 受众 | 带走什么 | 在哪一镜证明 |
|---|---|---|
| 所有人 | 只改两项设置，任何能填 Base URL 的客户端都能有记忆 | 03、04 |
| 开发者 | 网关在调用链上自动召回、执行工具、存回；客户端什么都不用实现 | 05 |
| 企业 | 一个地址，密钥集中管，记忆按人隔离，日志不存内容，模型照旧 | 06、07 |

## 写法原则（和 V1.3 的区别）

1. **用场景说话，不用定义说话。** 旁白讲人能感受到的变化（“它答得上来”），机制只在 05 镜讲一次，而且要跟着同一条消息走完。
2. **一个问题贯穿全片。** “上次定的发布日期是哪天？”在 01 镜答不上来，04 镜答上来，05 镜拆开看它怎么答上来的。
3. **旁白不带免责声明。** 事实边界写进本文末的护栏和动效指导，用画面选材来守住（例如不出现 Cursor），不把限定条件念出来、也不印在屏幕上。
4. **人物沿用团队版。** 用户“林夏”、同事“乔安”与《OpenViking 团队版》是同一组人，两支片子属于同一个世界。

## 逐镜

### 01｜又从零开始 · 00:00–00:09

**画面**
- 黑场淡入，近景只有一个聊天输入框。光标闪两下，字一个个打出来：`上次定的发布日期是哪天？`，回车。
- 回复按流式出现：`抱歉，我看不到之前的对话记录。能告诉我是哪个项目吗？`
- 回复刚落定，镜头缓缓后拉：同一个问题出现在另外几个窗口里（一个终端里的编程 Agent、一个企业自建的客服 Bot、一段 SDK 脚本的输出），每个都是“新对话”状态，回答都是空白或同一句“看不到之前的记录”。窗口顶部依次标着 `周一`、`周三`、`周五`。
- 左侧大字分两拍落下：`每次，` / `都从零开始。`

**旁白**
> 新开一个对话，模型就从零开始。你说过的话、定过的事，它都不记得。

**事实依据**：模型 API 无状态，客户端每次请求都要重发整段对话（`01-how-it-works.md` 首段）。

### 02｜每个应用都要接一遍 · 00:09–00:21

**画面**
- 镜头停在三个应用窗口上：`客服 Bot`、`知识助手`、`SDK 脚本`。每个窗口旁边开始“长出”集成工作：代码片段卡 `search_memory()` → `inject_context()` → `save_session()` → `extract_memory()`，一张叠一张，略带 ±2° 的错落，像团队版里文件版本越堆越高的镜头。
- 三个窗口同时在堆，工作量肉眼可见地翻了三倍。
- 再往右，一排机器图标显示 `安装插件… 3/12`；其中一个客户端图标变灰，标 `不支持插件`。
- 左侧大字：`每个应用，` / `都要再接一遍。`

**旁白**
> 想让它记住，就得给每个应用接一遍：检索、注入、保存。应用越多，这份活越重；有的客户端，连插件都装不了。

**事实依据**：官网“插件跑在 Agent 里……每台机器各装各升”“装不了插件的客户端……就用网关”。代码卡上的函数名是示意，不对应任何真实 SDK，屏幕上不标出处。

### 05｜跟着一条消息走 · 00:42–01:09（全片核心，一镜到底）

**画面**：镜头跟着右侧窗口里那条消息离开客户端，按顺序穿过整个世界（世界布局见动效指导第 2 节）。

| 段落 | 时间 | 镜头与动作 | 必须看清的东西 |
|---|---|---|---|
| a 出发 | 0–3s | 消息气泡收成一枚“消息胶囊”，胶囊上仍能读到原句；它沿弧线离开客户端，进入网关 | 是同一条消息，不是新图形 |
| b 召回 | 3–9s | 网关发出一道向下的检索光；镜头随之下降到 OpenViking 记忆库（带透视的平面，一排排文件卡）。`events/release-plan.md` 被扫中亮起，摘要 `2.0 发布从 12 月 1 日推迟到 12 月 8 日` 浮起 | 记忆是 OpenViking 里一个有路径的文件 |
| c 附加 | 9–12s | 记忆卡飞回网关，**贴在消息胶囊末尾**（不是塞进系统提示词），胶囊变长一截，尾部青色 | 记忆附在用户消息后面 |
| d 交给模型 | 12–15s | 胶囊离开网关进入右侧的上游模型节点；节点上轮流显示 Anthropic / OpenAI / DeepSeek / 火山方舟 标志，最后停在一个中性状态 | “你原来的模型”，网关不换模型 |
| e 工具往返 | 15–21s | 模型吐出一枚紫色调用条 `openviking_read(release-plan.md)`，飞回网关；网关下探 OpenViking，打开这份文件全文，摘出一行“原因：支付回归测试未完成”，送回模型。客户端窗口里同时只闪过一行灰字提示 | 模型决定读，网关执行，客户端不参与 |
| f 回复 | 21–24s | 模型生成的回复沿原路经网关回到客户端，04 镜那句完整回答逐字落定 | 用户只收到一条连贯回复 |
| g 存回 | 24–27s | 镜头略拉开：这一轮问答从网关落入 OpenViking 的会话区，几行对话收拢、结晶成一张新的记忆卡，插进记忆库 | 聊过的内容变成下一次的记忆 |

**旁白**
> 每来一条新消息，网关先去 OpenViking 找相关记忆，附在消息后面，再交给你原来的模型。要查得更细，模型会自己调用 OpenViking 工具，网关代为执行，把结果交回。你收到的，始终是一条完整的回复。聊过的内容存回 OpenViking，提炼成下一次的记忆。

**角标**：整镜右上角一个小标签 `原理示意`，不加其他说明文字。

**事实依据**
- 召回只针对用户新消息，附加在消息末尾，最多等 2 秒（`01-how-it-works.md`“模型看到什么”“使用须知”）。
- 召回结果带 URI，`detail="abstract"`；模型可用 `openviking_read` 展开原文（同上，开头内容示例）。
- 新建上下文配置默认开启只读工具；工具由网关执行，客户端每次调用只看到一行提示（`04-openviking-tools.md`、官网“模型自己翻资料”）。
- 保存晚一轮，提交后后台提取记忆（“对话什么时候保存”）。画面上 g 段是时间压缩，不画成实时发生。

### 06｜记忆跟着人走 · 01:09–01:21

**画面**
- 镜头横移回客户端区域。左边是一个终端风格的编程 Agent 窗口，顶部 `周一`：
  - `❯ 以后部署一律走 Helm，别再给我 Docker Compose 的方案。`
  - `好，以后都按 Helm 来。`
- 这段对话沿 05 镜建立好的路径落入 OpenViking，结晶成记忆卡 `部署用 Helm，不用 Docker Compose`。
- 镜头继续右移到另一个窗口：一个聊天应用，顶部 `周三`，用户换了客户端：`新服务怎么部署好？`
- 同一张记忆卡从 OpenViking 升起，贴上这条消息；回复：`按你的习惯，直接用 Helm。chart 可以这样组织……`
- 大字：`记忆跟着人走`

**旁白**
> 记忆跟着人走，不跟着客户端。周一在编程 Agent 里交代的习惯，周三换个聊天应用，它照样记得。

**事实依据**：官网“记忆跟着人走”原例。所有绑定同一 OpenViking 用户的客户端共享一份记忆；周一到周三的间隔覆盖了“停顿后保存、提交后提取”的时延。

### 07｜交给团队 · 01:21–01:39

**画面**
- 镜头升起，进入网关“内部”：一块高保真的网关控制台（参照开源 Studio 网关页，见动效指导第 6 节），标签栏 `概览 · 上游 · 上下文配置 · 密钥 · 请求日志 · 接入`，停在 `密钥`。
- 表格已有两行：`林夏 · Claude Code`、`乔安 · Cherry Studio`，每行带 `OpenViking 用户`、`上下文配置`、`上游` 列。光标点 `签发密钥`，弹出对话框，依次选 `给谁用`、`上下文配置`、`上游`，确认后新行 `ci-bot · 不存回 · 无工具` 滑入表格。
- 镜头在三处依次聚焦，每处只有一个动作，不用卡片说明：
  1. **服务商密钥不出服务器**：切到 `上游` 标签，服务商 API Key 显示为 `已保存`，一把小锁留在网关里，客户端侧只看到 `ovgw_…`。
  2. **记忆按人隔离**：画面下方 OpenViking 库分成林夏、乔安两条轨道，各自的记忆卡互不越界。

- 大字：`一个地址，全团队`

**旁白**
> 交给团队，也只需要一个地址。服务商密钥留在网关上，每人一把网关密钥，单独配置，随时吊销。记忆按人隔离，请求日志不存对话内容。原来用哪家模型，接着用哪家。

**角标**：控制台右上角小标签 `开源版界面示意`。云版控制台未定稿前，不画仿真云控制台。

**事实依据**：官网“给团队”整段；Studio 网关前端的标签栏与密钥表字段（`web-studio/src/i18n/locales/zh-CN/gateway/`）。上游支持 Anthropic、OpenAI、DeepSeek、火山方舟、BytePlus 方舟和自建兼容服务；“接着用哪家”指同一协议下的原有服务商。

## 事实护栏（制作时逐条对照）

1. **不出现接不进来的客户端。** Cursor、Trae 的请求从厂商服务器发出，接不了网关；画面里的客户端只用官网“你的客户端”名单中的：Cherry Studio、Open WebUI、Claude Code、Codex CLI、OpenCode、pi、OpenAI SDK、Anthropic SDK，以及无品牌的“自建应用”。
2. **记忆附在用户消息末尾**，不画成写进系统提示词，也不画成模型先调工具才拿到首次召回。
3. **工具默认只读。** 05 镜只演 `read`；`remember`、`add_resource` 等写入和导入工具不在主片出现（需要管理员开启，讲了反而要解释）。
4. **存回不是实时的。** 05g 和 06 都要有时间压缩的视觉暗示（角标或日期跳转），不说“立即变成记忆”。
5. **不说“数据不出门”。** 日志不存内容，但模型服务商会收到完整输入（含补充的记忆）。旁白只说“请求日志不存对话内容”。
6. **不说“兼容任何模型、任何客户端”。** 前提是能填 Base URL 和 API Key，且协议匹配（Anthropic Messages / OpenAI Chat Completions / OpenAI Responses）。这个前提放进发布页和文档，不进旁白。
7. **控制台是开源版界面示意**，不冒充云版控制台；聊天窗口是演示，不冒充某个客户端的真实界面（见动效指导第 6 节）。
8. **演示数据统一。** 发布日期“12 月 8 日”只是演示数据，避开 11 月，以免和产品发布时间混淆。
