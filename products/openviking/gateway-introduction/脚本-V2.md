## 一句话

**插件够不着的应用，改两项设置，也能用上 OpenViking 的记忆。**

主张来自官网“不装插件，不改代码，客户端就有记忆”。V2 把它放进 OpenViking 的整体版图：插件服务已有的 Agent，网关服务企业自己开发的 Agent 和工作流。两者不冲突。

## 看完要记住的四件事

| 受众 | 带走什么 | 证明它的镜头 |

## 写法原则

1. **先立前提，再提问题。** 先承认插件已经解决了一大片，观众就不会误以为“所有 Agent 都要接网关”，网关的定位也自然落在企业开发场景上。
2. **一个问题贯穿全片。** “上次定的发布日期是哪天？”在 02 镜答不上来，04 镜答上来，06 镜拆开看它怎么答上来。
3. **概念只讲一次，讲成人话。** 05 镜给出唯一的定义句，紧接着用“守在必经之路上”的类比，不出现 OpenAPI、MCP、hook 这类词。
4. **旁白不带免责声明。** 事实边界写在末尾护栏，靠选材守住。
5. **人物沿用团队版。** 用户林夏、同事乔安与《OpenViking 团队版》同属一个世界。

### 05｜网关是什么 · 00:46–01:02（新增）

**画面**
- 镜头从右窗口直接后拉、升高，第一次露出整张世界地图：左边是企业的应用（研发助手、客服 Bot，以及更多轮廓），中间是一道竖立的玻璃闸门（网关），右边是模型节点，闸门正下方是 OpenViking 记忆库。所有应用的模型请求都必须经过这道闸门。闸门顶部小字 `api.vikingdb.cn-beijing.volces.com`，正是 03 镜改进去的地址的域名。
- **开发者定义**（前半句旁白）：闸门亮起；“位于你的应用和模型之间”时，三个企业应用的模型调用线依次汇入闸门，闸门再连到模型。闸门正下方是通往 OpenViking 的竖直通道（与 06 镜同一条）。
- **人人能懂的类比**（后半句旁白），画面上两种做法并排对照，但仍在同一个世界里，不切成对比页：
  - 镜头先转到左侧的插件集群：8 个 Agent 依次挂上 OpenViking 小标记，下方一行“插件 · 装在每个 Agent 里，直连 OpenViking”，一条虚线直接通到 OpenViking 枢纽，不经过网关。
  - 镜头回到闸门，网关**守在通往模型的路上**：三个应用的“请求”依次进入闸门，通道向下一闪（标签“召回 ↓”），出来时变成“请求 + 记忆”送往模型；“回复”回来经过闸门时，通道再向下一闪（标签“存回 ↓”）。结尾镜头俯冲到研发助手窗口，正好落在 06 镜的首帧。
- 大字：`守在通往模型的路上`

**旁白**
> OpenViking 网关是一个模型代理，位于你的应用和模型之间。插件要装进每个 Agent；网关只守在通往模型的路上——每个应用经过这里，都自动带上记忆，也留下记忆。

**写法说明**
- 第一句给开发者：“模型代理”和“位于应用和模型之间”就是完整的技术定位。
- 第二句给决策者：不需要知道 OpenAPI、插件、网关的技术差别，只要看懂“装在每个里面”和“守在必经之路上”两种画面。
- 06 镜的“它在路上具体做了什么”就从这里自然展开。

**事实依据**：官网“OpenViking 网关是个模型代理”；“网关在客户端和模型服务商中间，客户端不直接接触 OpenViking，查和存都由网关代劳。插件则跑在 Agent 里面”。

### 06｜跟着一条消息走 · 01:02–01:28（全片核心，一镜到底，26 秒）

**画面**：镜头从 05 的全景俯冲回研发助手，接住那条消息，跟着它走完全程（样片：`project/renders/shot06/shot06-v2.mp4`）。网关与 OpenViking 之间只有一条竖直通道：召回、工具读取、存回都走这条通道，通道正下方是 OpenViking 枢纽（地面上的光环 + 立起的标志）。模型节点到达后展开成“推理面板”，带推理时间线。

| 段落 | 时间 | 镜头与动作 | 必须看清的东西 |
|---|---|---|---|
| a 出发 | 0–2.4s | 消息气泡收成“消息胶囊”，沿弧线进入网关 | 同一条消息，不是新图形 |
| b 召回 | 2.4–5.0s | 镜头下降；检索标签“检索：上次定的发布日期”沿通道下行，枢纽亮起，扫描环在地面扩散，`release-plan.md` 命中升起 | 召回是网关按新消息去 OpenViking 检索 |
| c 附加 | 5.0–6.6s | 记忆卡沿通道上行回到网关，贴在胶囊末尾 | 记忆附在用户消息后面 |
| d 交给模型 | 6.6–8.5s | 模型节点展开成推理面板；胶囊飞入后拆成三行输入：用户问题、召回的记忆（摘要）、工具定义（只读） | 模型拿到的是“问题 + 记忆 + 工具定义”，服务商标志轮换 |
| e 推理与工具往返 | 8.5–15.2s | 时间线播放头推进：输入 → 推理（结合记忆：12 月 8 日）→ 判断“摘要里没有原因，决定读取原文” → 调用工具。紫色调用条飞回网关，网关沿通道下行执行 `openviking_read`，原文从对应卡片位置升起并高亮原因，结果沿通道上行送回面板，成为第四行“工具结果”；时间线上这一段是“等待网关执行”的虚线 | 模型决定读，网关执行；模型在工具结果回来后继续推理 |
| f 继续推理与回复 | 15.2–19.6s | 时间线：继续推理 → 生成回复，面板“输出”区逐字出现答案；回复经网关回到应用，应用里依次出现召回摘要行、一行工具提示和完整回答 | 应用只收到一条连贯回复 |
| g 存回 | 19.8–26s | 镜头拉到全景；问答两行进入网关，沿同一通道下行（标签“存回 ↓ 本轮对话”），落入 sessions 成为 `gateway-0f3a`；“停顿 10 分钟后 · 提交 → 后台提取记忆”提示出现后，结晶成新记忆卡落入 `memories/events` | 先保存会话，提交后再提取记忆 |

**旁白**
> 每条新消息，网关先去 OpenViking 找相关记忆，附在消息后面，交给你原来的模型。要查得更细，模型会自己调用工具，网关代为执行。应用收到的，始终是一条完整回复；聊过的内容存回 OpenViking，变成下一次的记忆。

（旁白 20.2 秒按句切开放在画面节拍上：例如“附在消息后面”对上记忆贴附，“模型会自己调用工具”对上调用条飞出，“存回 OpenViking”对上通道下行。推理面板展开后约 1.5 秒无旁白，留给观众读输入三行。）

**角标**：整镜右上角 `原理示意`。

**事实依据**
- 召回只针对用户新消息，附在消息末尾，最多等 2 秒；超时则不带记忆照常发送（`01-how-it-works.md`）。
- 召回结果带 URI 和摘要；模型可用 `openviking_read` 展开原文（同上）。
- 新建上下文配置默认只开只读工具；工具由网关执行，客户端只看到一行提示（`04-openviking-tools.md`）。
- 保存晚一轮，提交后后台提取记忆；g 段为时间压缩。

## 事实护栏（制作时逐条对照）

1. **两份名单分开。** 01 镜星座用 Integrations 页第 2、3 档 Agent（含 Cursor、TRAE），表示插件接入；网关相关画面（03–09）不出现 Cursor、TRAE，它们的请求从厂商服务器发出，接不进网关。星座 Logo 也不画成“连入网关”。
2. **插件与网关不冲突，也不是升级关系。** 05、09 镜表现为两条并行的路。不说“网关替代插件”，也不说“网关更高级”。同一对话两者都在时，网关让出召回和存回，这一点不进主片。
3. **记忆附在用户消息末尾**，不画成写进系统提示词，也不画成模型先调工具才拿到首次召回。
4. **工具默认只读。** 06 镜只演 `read`；写入和导入工具不在主片出现。
5. **存回不是实时的。** 06g、07 要有时间压缩的视觉暗示。
6. **不说“数据不出门”。** 日志只记元数据（脱敏），但模型服务商会收到完整输入（含补充的记忆）。“安全和隐私都有保障”指网关一侧的密钥托管、按人隔离和日志脱敏，对外材料里不要延伸成“数据不出网关”。
7. **不说“兼容任何应用、任何模型”。** 前提是能配置模型的 Base URL 和 API Key，协议匹配（Anthropic Messages / OpenAI Chat Completions / OpenAI Responses）。前提写在发布页与文档里，不进旁白。
8. **界面性质。** 控制台标“开源版界面示意”；研发助手、客服 Bot、运维 Bot 都是演示用的虚构企业应用。
9. **演示数据。** 发布日期“12 月 8 日”只是演示数据，片中不出现产品的具体发布月份。
10. **不写具体的插件数量。** 官网的“14 个 harness”含命令行工具 ov CLI，Agent 实为 13 个；片中用“十余种 Agent 开箱即用”。
