# gtm-video

集中保存各产品视频的可重建工程，供制作、评审和后续修改复用。仓库保留生成视频所需的源文件；成片和构建中间产物不入库。

## 目录组织

按产品建立目录，每个视频独立管理：

```text
products/
  product-name/
    video-name/
      README.md
      .gitignore
      project/          # 动画、渲染、混音脚本和依赖锁文件
      assets/           # 必要的原始图片、Logo、字体等（也可放在 project 内）
      voiceover/        # 原始旁白、文本及时间戳
```

每个视频的 README 应写明标题、简介、语言、内容版本、制作/发布状态、素材来源和授权，以及环境版本、依赖安装命令、完整构建命令、输出位置和验证方法。外部发布后可附观看链接；不要将本地输出路径写成已上线的观看链接。

## 哪些内容需要上传

判断标准：从干净 checkout 能否重新生成相同内容、节奏和视觉效果的视频。

| 内容 | 要求与原因 |
|---|---|
| 动画与界面源码、渲染及混音脚本 | 保留完整构建链路，不依赖作者机器上的未提交脚本 |
| 分镜、旁白文本、时间线、剪辑点和配置 | 保留画面顺序、动作触发时间与音画同步关系 |
| 原始旁白及同步数据 | 使用旁白的项目须保留原始录音；字幕或剪辑依赖时间戳时一并保留（不限 JSON 格式）。重新调用 TTS 未必得到相同音色、停顿和时长，只有文本不足以复现 |
| 原始音乐、音效、图片、Logo、视频素材 | 保留实际需要且获准使用的输入素材；如果音效完全由脚本合成，保留脚本即可 |
| 字体及来源/许可说明 | 保留必要字体，或通过锁定版本的依赖恢复；不要依赖本机字体。可编辑中文模板需覆盖后续改文案所需字符 |
| 依赖清单及锁文件 | 如 package.json、package-lock.json；让渲染环境可恢复 |
| README 和验证脚本 | 说明重建、素材替换、常见修改点及质量验证方式 |

仍有复用价值的历史旁白和音色样本可以保留，但应标明当前版本使用哪些文件。大型原始素材若采用外部存储，需记录稳定位置、版本或校验值及获取步骤，不能只依赖会过期的临时下载链接。

## 哪些内容不要上传

| 内容 | 处理方式 |
|---|---|
| 最终 MP4、预览视频、历史导出版本 | 留在本地 review，或单独托管；不提交到 Git |
| 逐帧截图、生成样帧、联系表 | 放在忽略的渲染输出目录，由源码重新生成 |
| node_modules、浏览器安装包、虚拟环境 | 构建时安装，提交依赖清单和锁文件即可 |
| 合成音效、混音 WAV、拼接旁白预览 | 保留原始输入与生成脚本，不保留可重建输出 |
| 日志、缓存、系统文件 | 使用 .gitignore 排除 |
| API 密钥、令牌、带凭证的配置 | 不入库；必要时提供不含凭证的配置示例 |

不要按扩展名一刀切忽略所有 MP3、WAV、PNG 或 JSON：它们可能是不可替代的原始输入。优先按输出目录或明确的生成文件名设置规则。成片 MP4 与原始视频素材也应通过目录区分。

例如，本仓库网关介绍片使用：

```gitignore
node_modules/
/project/renders/
*.mp4
/project/audio/sfx_*.wav
/project/audio/*_mix.wav
/voiceover/full-preview.mp3
/voiceover-v2.1/timeline-preview.mp3
__pycache__/
*.py[cod]
.venv/
.DS_Store
```

以上是放在该视频目录里的规则，不应直接复制到不同结构的项目。网关工程不使用原始视频，因此可忽略全部 MP4；使用原始 MP4 素材的项目应只忽略导出目录。`.gitignore` 不会自动移除已被 Git 跟踪的产物，提交前仍需检查实际文件清单。

网关工程是一个实现示例，不要求后续项目沿用 HTML/GSAP、TTS 或相同目录细节；按实际工具链提供完整输入和重建方法即可。工程合入与成片对外发布是两个独立状态，合入不代表产品口径、素材使用范围或视频质量已获发布确认。

## 提交与评审流程

1. 在独立分支整理工程，补齐素材来源、使用授权、版本及构建说明；只提交已获准放入仓库的内容。
2. 从干净 checkout 安装依赖，检查音频、时间戳、字体和素材均可获取；不得依赖其他本地项目的路径。
3. 先生成关键帧检查文字、字体和布局，再完整渲染。关键帧要覆盖内容充分呈现时刻，而不只截每段开头。
4. 连续播放检查运镜、转场、字幕、旁白同步和音量；检查时长、分辨率、帧率、编码并执行完整解码。短暂闪烁需检查相邻帧，单张截图或解码成功不足以证明视觉正常。
5. 检查 `git diff --check`、`git diff --cached --stat` 和暂存文件清单，确认没有成片、截图、依赖和生成音频，再提交 PR。PR 写清变更、验证结果和待 review 内容。
6. 视频 review 记录以成片时间点为准；修复后重新渲染并复查相关片段和镜头衔接，更新同一 PR。生成视频只用于评审，不因此加入 Git。

网关工程的实践：原制作目录约 1.1 GB，其中包含依赖和大量逐帧截图；归档源码、必要素材、原始旁白及时间戳后，提交约 7.8 MB。这个体积是该项目的实例，不是其他项目的硬性上限。
